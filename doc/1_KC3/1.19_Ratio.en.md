# 1.19 Ratio

Ratios are made with a couple of large integers : the numerator
which can be any number, and the denominator which has to be positive.
They represent fractions of integral numbers.
They are written with a slash and no space.

```elixir
ikc3> 1/2 + 2/3
7/6
ikc3> 1/2 * 2/3
1/3
ikc3> 1/2 / 2/3
3/4
ikc3> 1/2 - 2/3
-1/6
```

Exponentiation requires an explicit number of significant precision bits:

```elixir
ikc3> require Ratio
Ratio
ikc3> Ratio.pow(4/9, 1/2, (Uw) 64)
2/3
ikc3> Ratio.pow(4/9, -1/2, (Uw) 64)
3/2
```

`Ratio.pow(base, exponent, precision_bits)` returns a Ratio. Exact
rational results are returned exactly. For an irrational real result
`y`, the returned rational approximation `r` satisfies
`abs(r - y) <= abs(y) / 2^precision_bits`. The precision must be a positive `Uw`;
there is no default. Numerators and denominators remain arbitrary-precision
Integers, including the components of the exponent.

For a negative base, the exponent is simplified first: an odd denominator
allows the real root, while an even denominator gives an error. Zero with
a negative exponent also gives an error. A zero exponent returns `1/1`.
The binary `**` operator does not choose a precision for Ratio powers;
use the explicit `Ratio.pow` call.

Approximation uses the logarithm and exponential series with argument
scaling and outward rational bounds. All arithmetic stays in Integers and
Ratios; the requested precision is verified against the resulting bounds.
See [NIST's logarithm series](https://dlmf.nist.gov/4.6.E4) and
[exponential series](https://dlmf.nist.gov/4.2.E19).
